# SPEC — «В бит», тренажёр читки рэпа

Документ для агента-исполнителя. Требования имеют ID (`REQ-…`); ссылайся на них в коммитах, тестах и отчётах. Если требование неоднозначно или противоречит прототипу — остановись и спроси, не выбирай сам.

## 0. Контекст

- **Продукт:** офлайн-приложение (PWA → APK через Capacitor), которое за 15–20 минут в день учит человека без вокального опыта читать рэп в бит. Язык интерфейса и текстов — русский.
- **Прототип:** `prototype/index.html` (один файл, ~300 строк JS). Это эталон поведения и визуала для этапа 1. Запусти его локально (`npx serve prototype`) и посмотри, прежде чем писать код.
- **Ключевой инсайт пользователя:** целые слова и ударные слоги в такт не попадают; помогает тихий тик на каждый слог. Поэтому ядро v1 — «лестница» (REQ-LAD), которая постепенно убирает подпорки, и корректная работа с ударениями и затактом (REQ-STR, REQ-LAY).

## 2. Типы (REQ-DATA)

```ts
// src/core/types.ts
export type Syllable = {
  text: string;                 // как отображать: 'КРАЛ', 'ко'; '' = пауза
  stressed: boolean;
  wordId: number;               // слоги одного слова имеют одинаковый wordId; пауза = -1
  onset: string;                // согласные до первой гласной, lowercase: 'кр' для 'крал', '' для 'у'
  stressSource: 'markup' | 'yo' | 'dict' | 'user' | 'none';
};
export type Beat = { syllables: Syllable[]; pickup?: boolean };  // слоги делят долю поровну
export type Bar = [Beat, Beat, Beat, Beat];                       // только 4/4
export type Line = { syllables: Syllable[]; pickupCount: number; beats: Beat[] };

export type LayoutMode = 'manual' | 'auto' | 'stress';
export type Text = {
  id: string; title: string; raw: string;
  mode: LayoutMode; perBeat: 1 | 2 | 3 | 4; lineStartsBar: boolean;
  targetBpm: number;
  stressOverrides: Record<string, number>;   // lowercase слово → индекс ударного слога
  lines: LineProgress[];                     // по индексу непустой строки
  updatedAt: number;
};
export type LadderStage = 1 | 2 | 3 | 4 | 5 | 6;
export type LineProgress = { stage: LadderStage; bpm: number; cleanStreak: number; failStreak: number };

export type Settings = {
  week: 1 | 2 | 3 | 4;
  tickVolume: number;      // 0..1, громкость тиков безударных слогов (базовая, лестница множит)
  leadMs: number;          // 0..150, упреждение подсветки
  outputOffsetMs: number;  // калибровка вывода звука, >= 0
  inputOffsetMs?: number;  // калибровка микрофона (этап 4)
};
export type Progress = {
  days: string[];          // 'YYYY-MM-DD' по локальному времени
  sessions: number; breathBestSec: number; countBest: number;
  recordings?: { date: string; blobKey: string; textId?: string }[];
};
```

REQ-DATA-1. Хранение — IndexedDB через `idb-keyval` (или аналог ≤ 2 КБ gzip). У корня данных есть `schemaVersion: number` и функция миграций.
REQ-DATA-2. При первом запуске импортировать данные прототипа из `localStorage`: `vbit_week` (0..3 → 1..4), `vbit_text` (`{mode,n,nb,text,bpm}` → один `Text`), `vbit_days`, `vbit_total`, `vbit_breath`, `vbit_count`, `vbit_mMode`, `vbit_mSet`, `vbit_mBpm`. После импорта ключи не удалять.
REQ-DATA-3. Экспорт/импорт всех данных, кроме аудиозаписей, одним JSON-файлом (скачивание + выбор файла).

## 3. Слоги (REQ-SYL)

```ts
export function syllabifyWord(word: string): string[];
export function syllabifyLine(line: string): { text: string; wordId: number; onset: string }[];
```

REQ-SYL-1. Гласные: `аеёиоуыэюя` и латинские `aeiouy` (регистр не важен). Слово с 0–1 гласной = один слог.
REQ-SYL-2. Граница между соседними гласными `a` и `b` (индексы) со скоплением согласных `C = word[a+1..b-1]`:
  1. если в `C` есть `ь` или `ъ` → граница сразу после последнего из них;
  2. иначе если `|C| ≥ 2` и первая согласная `C` ∈ `рлмнй` → граница после неё;
  3. иначе → граница сразу после гласной `a` (все согласные уходят вправо).
REQ-SYL-3. Регистр букв сохраняется в выводе.
REQ-SYL-4. `syllabifyLine`: удаляет пунктуацию (кроме `-` и `+`), режет по пробелам и дефисам. Слово без гласных (`в`, `к`, `с`, `б`) приклеивается спереди к первому слогу следующего слова; если следующего нет — сзади к последнему слогу. Цифры удаляются, и `parse`/`layout` возвращают предупреждение `digits_removed`.
REQ-SYL-5. Тест-векторы (обязательны, точное совпадение):

| вход | выход |
|---|---|
| мама | ма-ма |
| кораллы | ко-рал-лы |
| большой | боль-шой |
| сушку | су-шку |
| мойка | мой-ка |
| семья | семь-я |
| подъезд | подъ-езд |
| шоссе | шо-ссе |
| сестра | се-стра |
| карта | кар-та |
| лампа | лам-па |
| поэт | по-эт |
| ёжик | ё-жик |
| пришёл | при-шёл |
| Клары | Кла-ры |
| строка `в дом` | `вдом` (1 слог) |
| строка `к нам пришёл` | `кнам`-`при`-`шёл` |
| строка `кто-то` | `кто`-`то` (2 слова) |

Добавь ещё ≥ 12 своих векторов, включая латиницу и строку из одних знаков препинания (→ пустой массив).

## 4. Ударения (REQ-STR)

```ts
export function applyStress(syls: Syllable[], opts: { overrides: Record<string, number>; dict?: StressDict; lineStart: boolean }): Syllable[];
```

Приоритет источников (первый сработавший побеждает): `user` (overrides) → `markup` → `yo` → `dict` → `none`.

REQ-STR-1 (markup, `+`). `+` перед гласной делает её слог ударным: `кор+аллы` → `ко-РАЛ-лы` (stressed на 2-м слоге). Сам `+` из текста удаляется.
REQ-STR-2 (markup, капс). Слог ударный, если все его буквы заглавные **и** длина ≥ 2. Однобуквенный заглавный слог (`Я`, `У`) ударный, только если он не первый слог строки.
REQ-STR-3 (ё). Слог с `ё` ударный.
REQ-STR-4 (dict). Словарь ударений подключается на этапе 2. Агент предлагает 1–2 открытых словаря с лицензией и размером и ждёт подтверждения. Требования: лицензия, допускающая встраивание; ≤ 5 МБ gzip; ленивая загрузка (не в основном бандле); поиск по lowercase-слову; омографы (`замок`) возвращают несколько вариантов → `stressSource: 'none'` + флаг `ambiguous`.
REQ-STR-5. Служебные слова без ударения по умолчанию: `и а но да в во на по к ко с со у о об от до за из не ни же ли бы то`.
REQ-STR-6. В режиме `manual` dict не применяется — только markup, ё, user.
REQ-STR-7. UI: в превью раскладки тап по слогу переключает ударение и пишет `stressOverrides[word] = index` (или удаляет). Слова со `stressSource: 'none'` и ≥ 2 слогами подсвечены как «проверь ударение».

## 5. Разметка (REQ-PAR)

```ts
export function parseManual(raw: string, opts: { lineStartsBar: boolean }): { lines: Line[]; warnings: Warning[] };
```

REQ-PAR-1. Строка текста = строка ввода; пустые строки пропускаются.
REQ-PAR-2. `|` — граница доли. Внутри доли слоги разделяются пробелом или `-`. `_` — пустой слог (пауза). Пустая доля (`| |`) = одна пауза.
REQ-PAR-3. Затакт: строка, начинающаяся с `>`, считает первый сегмент (до первой `|`) затактом (`pickup: true`). Пример: `> на дво- | РЕ тра- | ВА на тра- | ВЕ дро- | ВА`.
REQ-PAR-4. Строка с текстом, но без `|` → `warning: no_beat_separators`, вся строка — одна доля.
REQ-PAR-5. Тест-вектор: `КАРЛ у | КЛА-ры у- | КРАЛ ко- | РАЛ-лы` → 4 доли: `[КАРЛ*, у] [КЛА*, ры, у] [КРАЛ*, ко] [РАЛ*, лы]` (`*` = stressed).

## 6. Раскладка (REQ-LAY)

```ts
export function layout(text: Pick<Text, 'raw' | 'mode' | 'perBeat' | 'lineStartsBar' | 'stressOverrides'>, dict?: StressDict): { bars: Bar[]; lines: Line[]; warnings: Warning[] };
```

REQ-LAY-1 (`auto`). Слоги строки идут подряд по `perBeat` на долю; последняя доля строки добивается паузами до `perBeat`.
REQ-LAY-2 (`stress`). Для каждой строки:
  1. затакт = безударные слоги до первого ударного;
  2. группа = ударный слог + все безударные до следующего ударного;
  3. группа из `k ≤ 4` слогов → одна доля из `k` слогов; `k > 4` → `ceil(k/4)` долей, слоги делятся поровну, остаток — в первые доли;
  4. строка без ударных → ведёт себя как `auto` с `perBeat = 2` + `warning: no_stress`.
REQ-LAY-3 (затакт, все режимы). Затакт из `p` слогов играется в последних `p` слотах доли, предшествующей первой доле строки; эта доля делится на `max(p, 2)` слотов, если `p ≤ 4`, иначе на `p`. Если предшествующая доля не пауза — вставляется доля-пауза (строка сдвигается на долю) + `warning: pickup_shifted`. Перед первой строкой текста эту роль играет 4-я доля отсчёта.
REQ-LAY-4. `lineStartsBar = true` → после строки добавляются доли-паузы до конца такта (с учётом REQ-LAY-3).
REQ-LAY-5. Кнопка «В разметку»: `serializeManual(lines): string` превращает любую раскладку в текст разметки (капс для ударных, `>` для затакта). `parseManual(serializeManual(x))` даёт ту же раскладку (property-тест).
REQ-LAY-6. Снэпшот-тесты раскладки: «Карл у Клары» (manual), «Шла Саша по шоссе и сосала сушку» (auto, 2), `> на дво- | РЕ тра- | ВА на тра- | ВЕ дро- | ВА` (затакт), строка только из `_`, пустой ввод.

## 7. Паттерны метронома (REQ-PAT)

REQ-PAT-1. `drillBar(mode: 1|2|3|4|'auto', set: 'taka'|'pbdg'|'rand', barIndex: number, rng: () => number): Bar`.
REQ-PAT-2. `auto`: количество слогов на долю по номеру такта: `[1,2,4,3][floor(barIndex/2) % 4]`.
REQ-PAT-3. Наборы: `taka` = та/ка/ти/ки, `pbdg` = па/ба/да/га (первые n), `rand` = согласная из `бвгдзклмнпрстфхшжч` + гласная из `аоуиэы`. Первый слог каждой доли в дриллах — `stressed: true`.
REQ-PAT-4. `rng` инжектится (для тестов — seeded).

## 8. Таймлайн (REQ-TL)

```ts
export type TickKind = 'downbeat' | 'beat' | 'stressed' | 'unstressed' | 'rest';
export type TimelineEvent = { time: number; bar: number; beat: number; slot: number; slots: number; kind: TickKind; gain: number };
export function beatEvents(bar: Bar, barIndex: number, beatIndex: number, beatStart: number, spb: number, mix: Mix): TimelineEvent[];
```

REQ-TL-1. Доля с `n` слогами: событие слота `s` во время `beatStart + s * spb / n`.
REQ-TL-2. `kind`: слот 0 доли 0 — `downbeat`; слот 0 других долей — `beat`; прочие слоты — `stressed` / `unstressed` / `rest` по слогу. Ударный слог на слоте 0 остаётся `downbeat`/`beat`.
REQ-TL-3. `gain` берётся из `Mix` (REQ-SND + ступень лестницы). Пауза — `gain: 0`, событие для UI всё равно есть.
REQ-TL-4. Тест: при 90 BPM время начала доли № 4000 = `4000 * 60/90` с погрешностью < 1e-6 с; события строго возрастают по времени.

## 9. Звук (REQ-SND)

Синтез Web Audio (осциллятор + огибающая ~45 мс), без сэмплов.

| kind | звук | gain по умолчанию |
|---|---|---|
| downbeat | синус 1400 Гц | 0.55 |
| beat | синус 950 Гц | 0.55 |
| stressed | «деревянный» клик: треугольник 420 Гц, атака 2 мс, спад 60 мс | 0.33 |
| unstressed | синус 650 Гц | 0.14 × `settings.tickVolume` × множитель ступени |
| rest | — | 0 |

REQ-SND-1. Слайдер «Тики слогов» 0–100% заменяет чекбокс прототипа (по умолчанию 100% = 0.14).
REQ-SND-2. Сигнал конца шага тренировки: два тона 880 и 1320 Гц через 170 мс.

## 10. Аудио-движок (REQ-AUD)

REQ-AUD-1. Единственный источник времени — `AudioContext.currentTime`. Планировщик: `setInterval` 25 мс, планирует все события, у которых `time < currentTime + 0.12`. Для звука никаких `setTimeout` и `<audio>`.
REQ-AUD-2. Такты получаются лениво через `getBar(i)` и мемоизируются на время проигрывания (случайные слоги не меняются между показом и звуком).
REQ-AUD-3. Синглтон: старт нового плеера останавливает текущий и вызывает его `onStop`.
REQ-AUD-4. BPM 40–180, меняется на лету со следующей доли. Начало следующей доли = предыдущее + `60/bpm` (float, без округления).
REQ-AUD-5. UI получает события через очередь и `requestAnimationFrame`: событие отдаётся UI, когда `currentTime ≥ event.time − leadMs/1000 + outputOffsetMs/1000`.
REQ-AUD-6. `AudioContext` создаётся/возобновляется только из обработчика жеста пользователя.
REQ-AUD-7. Wake Lock на время проигрывания (PWA: Screen Wake Lock API; Capacitor: плагин keep-awake). Повторный запрос при `visibilitychange → visible`.
REQ-AUD-8. `visibilitychange → hidden` или смена экрана → стоп звука и пауза таймера шага.
REQ-AUD-9. Отсчёт: перед текстом всегда один такт `1 2 3 4` (только щелчки долей).

## 11. Калибровка (REQ-CAL)

REQ-CAL-1. Экран настроек «Калибровка»: 16 щелчков при 90 BPM, пользователь тапает по большой кнопке в такт. Первые 4 тапа игнорируются. `outputOffsetMs = clamp(median(tapTime − clickTime), 0, 400)`. Повторить / сбросить.
REQ-CAL-2. Если доступен `AudioContext.outputLatency`, показать его рядом как подсказку (не складывать с калибровкой).

## 12. Тренировка (REQ-SES)

REQ-SES-1. Шаги перенести из массива `STEPS` прототипа в `src/data/steps.json` без изменения текстов: 17 шагов, ~18,5 мин. Поля: `block, title, durationSec, body, list?, kind?` (`kind` ∈ `breath | count | ends | drill | karl | mytext`).
REQ-SES-2. Неделя 1–4 задаёт BPM ритм-шагов: 75 / 80 / 85 / 90; подсказки недель — из `WEEKS` прототипа. В шаге `drill` тики слогов включены для недель 1–2.
REQ-SES-3. Управление: Назад / Старт-Пауза-Продолжить / Дальше. Таймер обратного отсчёта; на нуле — сигнал (REQ-SND-2), кнопка меняется на «Дальше». Для ритм-шагов старт и пауза запускают и останавливают и таймер, и плеер.
REQ-SES-4. `breath`: секундомер «Начал выдох / Закончил», лог попыток, рекорд в `Progress.breathBestSec`. `count`: поле числа 1–300 с инлайн-ошибкой, рекорд в `countBest`. `ends`: показывает первую непустую строку текущего текста (без разметки).
REQ-SES-5. `mytext` (v1): открывает LineDrill (REQ-LAD) по строке с наименьшей ступенью текущего текста. Если своего текста нет — пример «Шла Саша» + подсказка.
REQ-SES-6. Финал: добавить сегодняшнюю дату в `days` (без дублей), `sessions++`, показать серию дней (последовательные дни, заканчивающиеся сегодня или вчера).

## 13. Лестница (REQ-LAD)

Экран LineDrill: одна выбранная строка (или 2–4 подряд) из текста, проигрывается по кругу, после отсчёта.

| ступень | что на экране | тики безударных (множитель) | stressed-клик |
|---|---|---|---|
| 1 Скелет | вместо слогов «та», ударные «ТА» | 1.0 | да |
| 2 Слоги | слоги в отдельных ячейках | 1.0 | да |
| 3 Слова | ячейки одного слова склеены (общий фон, скругление только по краям слова, даже через границу доли) | 0.5 | да |
| 4 Доли | как 3 | 0 | да |
| 5 Чистый бит | караоке: строка обычным текстом, подсвечен текущий слог, ударные подчёркнуты | 0 | нет |
| 6 Наизусть | караоке, слова свёрнуты до первой буквы | 0 | нет |

REQ-LAD-1. `ladder.ts` — чистые функции: `mixForStage(stage): Mix`, `renderModeForStage(stage)`, `nextState(state: LineProgress, result: 'clean'|'fail', targetBpm): LineProgress`.
REQ-LAD-2. Правила `nextState`: старт ступени — `bpm = round(targetBpm * 0.7)`. `clean` → `cleanStreak++`, `failStreak = 0`; при `cleanStreak == 3` → `bpm = min(targetBpm, round(bpm * 1.05))`, `cleanStreak = 0`; если `bpm` уже был равен `targetBpm` → `stage + 1` (макс 6), `bpm = round(targetBpm * 0.7)`. `fail` → `failStreak++`, `cleanStreak = 0`; при `failStreak == 2` → `bpm = max(40, round(bpm * 0.95))`, `failStreak = 0`.
REQ-LAD-3. После каждого круга — кнопки «Чисто» / «Сбился» (крупные, внизу экрана). Плеер не останавливается; нажатие применяется к последнему завершённому кругу. Без нажатия круг не считается.
REQ-LAD-4. Ручной выбор ступени 1–6 и сброс прогресса строки.
REQ-LAD-5. Прогресс хранится в `Text.lines[i]`; при изменении текста строки, у которых изменилось содержимое, сбрасываются на ступень 1.

## 14. Подсветка и онсет (REQ-VIS)

REQ-VIS-1. Сетка такта: 4 пэда с подписью доли (РАЗ / два / три / четыре); ширина < 560 px → 2×2. Под текущим тактом — превью следующего (бледнее, без подписей). Ячейки не переносят слоги по буквам (`white-space: nowrap`).
REQ-VIS-2. Упреждение `leadMs` (по умолчанию 60) — REQ-AUD-5.
REQ-VIS-3. У слога с `onset.length ≥ 2` начальные согласные отрисованы бледнее и сдвинуты влево на 0.35em (визуальный намёк «начни раньше щелчка»).
REQ-VIS-4. Ударный слог: жирный + подчёркивание 2 px акцентным цветом.
REQ-VIS-5. Тема из прототипа: фон `#17131c`, панели `#221d29`/`#2c2535`, линии `#3a3245`, текст `#f4efe8`, приглушённый `#aca3b8`, акцент `#ff5a3c`. Заголовки Unbounded, текст Manrope. Нижняя навигация. Кнопки ≥ 44 px, видимый фокус, `prefers-reduced-motion` отключает анимации.

## 15. Метроном и Тексты (перенос прототипа)

REQ-MET-1. Экран «Метроном»: режимы 1/2/3/4/Авто, наборы taka/pbdg/rand, BPM (слайдер, ±1, TAP — среднее по последним тапам в окне 3 с, нужно ≥ 3), слайдер тиков. Состояние запоминается.
REQ-TXT-1. Экран «Тексты»: список текстов (создать, переименовать, удалить с подтверждением в UI, не `confirm()`), редактор: режим manual/auto/stress, perBeat (для auto), «каждая строка с нового такта», превью раскладки по тактам с предупреждениями, кнопка «В разметку», плеер, кнопка «Разобрать строку» → LineDrill.
REQ-TXT-2. Встроенные примеры — только из прототипа (скороговорки и учебный куплет). Тексты чужих песен в код, тесты и фикстуры не добавлять.

## 16. Микрофон (REQ-MIC, этап 4)

REQ-MIC-1. `getUserMedia` + `AudioWorklet`; аудио не покидает устройство.
REQ-MIC-2. Детектор онсетов: энергия в полосе 300–3000 Гц или spectral flux, порог адаптивный. Сопоставление: для каждого ожидаемого слога — ближайший онсет в окне ± половина слота.
REQ-MIC-3. Калибровка входа: 8 щелчков через динамик (без наушников), медиана задержки распознанных щелчков → `inputOffsetMs`.
REQ-MIC-4. Результат круга: у каждой ячейки метка вовремя (±40 мс) / рано / поздно / пропущен; итог % и среднее смещение в мс. Круг `clean`, если ≥ 85% слогов вовремя и все ударные вовремя. Результат подаётся в `nextState` вместо ручных кнопок (кнопки остаются как override).
REQ-MIC-5. Шаг «Запись»: запись в IndexedDB (одна в день, перезапись), экран Progress проигрывает «сегодня» и «7 дней назад».
REQ-MIC-6. Валидация: набор из 10 записей, размеченных вручную; детектор находит ≥ 80% слогов с ошибкой ≤ 30 мс. Если нет — оценивать только ударные слоги и сообщить.

## 18. Обязательные e2e (Playwright, viewport 390×844)

- Каждый экран открывается без ошибок в консоли (`pageerror` и `console.error` = провал).
- Метроном: старт → в течение 2 с хотя бы одна ячейка получила активный класс.
- Тренировка: «Дальше» × 17 → экран финала, серия дней ≥ 1.
- Тексты: ввод `КАРЛ у | КЛА-ры у- | КРАЛ ко- | РАЛ-лы` → превью показывает 1 такт из 4 долей.
- Нигде нет горизонтальной прокрутки (`document.documentElement.scrollWidth <= 390`).
- Запуск с `--autoplay-policy=no-user-gesture-required`.
