# CLAUDE.md — «В бит»

Ты реализуешь приложение по `SPEC.md`. Прочитай его целиком перед любой работой. Эталон поведения — `prototype/index.html` (запуск: `npx serve prototype`).

## Как работаем

- Один этап из `SPEC.md` §17 за сессию. В начале этапа — план (список задач с ID требований) и вопросы. Код не пиши, пока я не ответил «ок».
- В конце этапа — отчёт: что сделано (по REQ-ID), что нет и почему, как проверить на телефоне. Потом стоп. Следующий этап не начинай сам.
- Неоднозначность или расхождение SPEC и прототипа → спроси. Не выбирай молча.
- Коммиты маленькие, сообщение начинается с REQ-ID: `REQ-SYL-2: ь/ъ boundary rule`.

## Команды

```bash
npm run dev          # локально
npm run lint
npm test             # vitest
npm run build
npx playwright test  # e2e
```

Перед словами «готово» все четыре проверки (`lint`, `test`, `build`, `playwright`) зелёные. Вставь их вывод (хвост) в отчёт.

## Правила кода

- Логика ритма, слогов, ударений, раскладки, лестницы — только в `src/core/`, чистые функции, без DOM/Vue/Web Audio. Сначала тест, потом реализация.
- Тест-векторы из SPEC переносятся в тесты дословно. Если вектор не проходит — чини код, не вектор. Если считаешь вектор ошибочным — спроси.
- Аудио: время только из `AudioContext.currentTime`, lookahead-планировщик (REQ-AUD-1). Не «упрощай» движок на `setTimeout`/`<audio>`/Tone.js.
- Новая npm-зависимость — только после моего «ок» (назови пакет, размер, лицензию, зачем).
- Не используй `alert`/`confirm`/`prompt` — диалоги в UI.
- Не добавляй тексты чужих песен ни в код, ни в тесты, ни в фикстуры.
- Не трогай `prototype/` — он только для чтения.
- UI-тексты — на русском, в sentence case, без восклицательных знаков.
